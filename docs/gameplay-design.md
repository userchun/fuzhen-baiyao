## 0. 定位（原简纲）

**一句话**：守在城墙上画符镇妖，用五行相克和符咒相生，挡住一波比一波凶的百鬼夜行。

**给谁玩**：喜欢割草肉鸽的竖屏手游玩家，想要一局 3 分钟、越打越爽的构筑成长感。

**核心循环**：拖动底部移动、按住战场瞄准连发 → 击杀得灵气、升级三选一 → 两个相生符咒到 3 级触发合击 → 击败 Boss 过关 → 结算拿铜钱、符纸 → 局外升级 → 再打下一关。

**参考**：吸血鬼幸存者 + 塔防守墙，保留"自动攻击 + 三选一升级"，去掉自由移动地图，局外成长只做轻量加成。画面可读性参考休闲竖屏俯视射击，画风气质参考暗黑西游卡牌，都不照搬。

**美术方向**：暗黑国风 Q 版，详见 `docs/art/art-bible.md`。

**不做**：
- 会改变局内玩法的局外系统（法器、角色、皮肤）、道行等级、护符、符咒分支
- 付费货币、体力、联网、排行榜、云存档
- 第三关及以后（方向见第 5 节，暂不开发）

## 1. 一局的流程

菜单 → 选关 → 战斗 → 结算并记账 → 奖励展示 → 回到局外养成。活动战斗时长口径见第 5 节；开箱动画不是实际发奖时点。

**胜负规则**：击败本关最终 Boss 即胜利，不要求清完杂兵；Boss 开始播死亡动作时就停止刷怪。城墙血量归零即失败。🛠 补充两条：
- 同一帧里城墙归零和 Boss 死亡同时发生，算失败。
- 🧪 战斗最长 240 秒（暂停、选卡、切后台不计时），超时算失败，210 秒时提前提示。
- 🛠 每个仿真步先结算伤害，再依次检查墙破、Boss 致命、超时、升级选卡。Boss 致命当步锁定胜利或失败，不等死亡动画结束才判；锁定后停止战斗与计时，只播演出，缺死亡素材直接进入结算。
- 🛠 活动时间不包含选卡、暂停、后台和顿帧；超时属于失败，主动退出单独记为退出。退出进程不支持续战，未产生持久结算的本局不发奖，已持久结算按第 3.2.1 节恢复。

### 1.1 暂停与设置 🛠

- 局内右上角放暂停按钮；切到后台时自动暂停。选卡时游戏本来就是暂停的。
- 暂停菜单有四项：继续、音乐开关、音效开关、退出本局。
- 退出本局的收益按第 3.2 节“退出”行结算，日志不混为自然失败；奖励是否可刷需通过收益 / 时间测试，不能仅凭按存活时间计算就认定不会刷。
- 切回前台显示继续按钮，清除旧触摸和积压时间；不能自动恢复按住射击或补刷后台波次。
- 主界面右上齿轮进入"设置"，有四项：音乐开关、音效开关、震屏开关、清除存档（要二次确认）。设置项存进存档的 `settings` 字段。

- 精英占一个槽，分裂出的狐火作为新怪重新排队；退出、重开关卡清空槽位、队列和预算历史。

**Boss 通用规则** 🛠
- 出场动作（12 帧，缺图按 1.2 秒）期间无敌，不移动、不召唤。

**白骨换相与化骨** 🛠（新增数值为 🧪）
- 阈值精确为本局最大生命的 `2/3`、`1/3`，UI 可显示约 67%、33%；按显式阶段编号推进，不用扣血后的比例直接跳到最终相。
- 伤害跨阈值时，先取消未释放的普通攻城 / 召唤动作，再进入下一相，把生命设为该血段顶部，舍弃跨阈值的溢出伤害，然后以新属性开始 2.5 秒化骨蓄力。进入同一相只触发一次。
- 蓄力中不移动、不普通攻城、不召唤，免疫普通冻结；伤害仍有效，但非最终相最低降至下一换相阈值，避免蓄力中再次换相。蓄力 / 专属眩晕结束后，下一次命中才可推进下一相。最终相可被击杀，致命时立即取消未释放技能。

重复通关减半仅指基础胜利铜钱，不把精英奖励或宝箱再减半。其实际引导效果需比较收益 / 分钟，不先认定能避免刷第一关。

**结算口径与顺序** 🛠
- 首通按“关卡 + 难度”分别判断；普通首通发本表普通首通项，困难首通使用常规重复胜利基数，再另发困难首通符纸，不重复发普通首通箱或普通首通符纸。
- `F = min(5 × floor(t / 10), 本关失败上限)`，`t` 为第 1 节活动时间；每个实际击杀精英只记一次，未杀死不发精英奖励。Boss、召唤小怪、分裂狐火不是精英奖励来源。
- `E = 10 × 精英击杀数`；`B` 为第 3.3 节各已获得铜箱结果之和。常规收益先相加，再乘难度倍率 `M`（普通 1、困难 2），最后加不参与倍率的首通项。

| 结果 | 倍率前基础铜钱 / 符纸 | 精英 +10 与铜箱 | 额外首通项 |
|---|---|---|---|
| 普通首次胜利 | 普通首通基础铜钱 / 0 | 发放 | 普通首通符纸 + 普通首通箱 |
| 普通重复胜利 | 重复通关铜钱 / 重复通关符纸 | 发放 | 无 |
| 困难首次胜利 | 重复通关铜钱 / 重复通关符纸 | 发放，和基础收益一起 ×M | 困难首通符纸，只加一次 |
| 困难重复胜利 | 重复通关铜钱 / 重复通关符纸 | 发放，和基础收益一起 ×M | 无 |
| 自然失败 / 超时 | F / 0 | 发已实际击杀的精英收益，整体 ×M | 无，不置首通 |
| 主动退出 | F / 0 | 不发，已记击杀的精英奖励也取消；F 按 M 计算 | 无，不置首通 |

普通首通行的基础及精英也统一按 M 计算（普通 M=1）；普通首通箱作为额外项只开一次。主动退出与自然失败可能有不同收益，但相同时间的退出不会比自然失败多。

**完整算例** 🧪
- 荒村普通首通，杀 3 个精英，三个铜箱分别为 `(40铜钱,1符纸)`、`(40,0)`、`(40,1)`，银箱为 `(80,1)`：铜钱 `100 + 3×10 + 120 + 80 = 330`，符纸 `5 + 2 + 1 = 8`。
- 荒村困难首通，杀 5 个精英，五个铜箱各 40 铜钱、符纸合计 3：铜钱 `(50 + 5×10 + 200) ×2 = 600`，符纸 `(2 + 3) ×2 + 10 = 20`，无普通首通银箱。
- 荒村普通 65 秒退出：`F=30`，即使之前杀过精英，也只发 30 铜钱、0 符纸；同时间自然失败则额外保留已击杀的精英奖励与箱子。

### 3.2.1 一次性记账 🛠

- 每局开局生成唯一的 `runId`。结算时把铜钱、符纸、首通记录和 `runId` 一次写进存档。
- 已经记过账的 `runId` 不会再发奖：重开结算界面、结束事件触发两次、保存重试，都不会重复加钱。
- 先冻结结果、抽好所有箱子，再将完整 `pendingSettlement` 持久化；随后一次提交余额、首通、最佳时间、`lastSettlement` 并清空 pending。两个提交阶段、字段及备份见第 4.3 节。
- 所有写入成功后才播放奖励展示，可跳过动画。展示数字是已提交结果，不能在逐项动画回调里实际加钱；反复打开、恢复、重播不得重抽宝箱。
- 保存失败时保留内存待提交结果，禁止消费、开下一局，允许重试；pending 已写入成功后可跨进程恢复，首次持久化本身失败时不能承诺关闭应用后不丢结果。UI 必须区分“待保存”与“已保存”。这只保证本地逻辑一致，不当作防作弊。

### 3.3 宝箱 🧪

| 档位 | 铜钱 | 符纸 |
|---|---|---|
| 铜箱 | 30–50 | 0–1 |
| 银箱 | 60–100 | 1–2 |
| 金箱 | 120–200 | 3–5 |

局内每杀 1 只精英（灯笼鬼）登记 1 个铜箱，按第 3.2 节决定是否结算。普通波次配置荒村 3 只、古寺 5 只；困难新增数量见第 5 节，不能按配置总数直接发箱，必须实际击杀。

🛠 箱子铜钱在闭区间内按整数等概率抽取，符纸在对应整数范围独立等概率抽取。结果在 pending 首次写入前确定并保存，不在点击开箱时抽取。宝箱不消耗背包位置，不保留为以后可反复点击的道具。

### 3.4 产出消耗目标 🧪

- 以下是箱子等概率时的数学期望，假设胜局实际杀掉全部配置精英，不是混合胜败后的真人平均收入。失败、退出、漏杀精英须按第 3.2 节单独统计。

| 场景 | 精英数 | 铜钱期望 | 符纸期望 |
|---|---:|---:|---:|
| 荒村普通首通 | 3 | 330 | 8 |
| 古寺普通首通 | 5 | 560 | 14.5 |
| 荒村普通重复胜利 | 3 | 200（范围 170–230） | 3.5 |
| 古寺普通重复胜利 | 5 | 325（范围 275–375） | 5.5 |
| 荒村困难重复胜利 | 5 | 600 | 9 |
| 古寺困难重复胜利 | 7 | 850 | 13 |

困难首通在困难重复胜利期望上另加本关首通符纸，奖励规则只在第 3.2 节定义。收益提高是否匹配难度与用时，要用实际收益 / 分钟验证。

- 现价格四项属性共需 **2,118 铜钱**，六符从 0 到 3 星共需 **114 符纸**；满级成本以第 4 节表为准，不再承诺两种资源“约 20 局同步满”。
- 示例路线：前两局分别首通荒村、古寺，此后按荒村、古寺交替重复普通胜利，不挑战困难，全部击杀精英；累计产出如下，已经花掉的资源也计入累计，不是余额。

| 完成胜局数 | 累计铜钱期望 | 累计符纸期望 | 按期望可支持的培养 |
|---|---:|---:|---|
| 5 | 1,615 | 35 | 尚不足四属性全满；可优先培养常用项 |
| 10 | 2,990 | 58.5 | 四属性成本已覆盖，符咒仍需选择主用符升星 |
| 20 | 5,615 | 103.5 | 属性已满，符咒接近全满 |

这条理想胜局路线约第 7 胜覆盖属性成本、第 23 胜覆盖符纸成本；困难会显著加速，早败会延长。先承认铜钱较早满、后期剩余铜钱无新增用途，不另造强制消耗；若试玩需要更长培养周期，重新调奖励或价格并重算整表，不用“20 局”倒填结果。

## 4. 局外养成 🛠

最早的简纲写"不做局外养成"，2026-10-30 改为做一套轻量版：只加基础属性，不改变局内构筑的玩法。

### 4.1 城墙与道士属性 🧪

除开坛外各项 5 级封顶。🛠 第 n 级价格为 `floor(首级价 × 1.3^(n-1) + 0.5)`，从首级价计算后四舍五入，不用上一次取整后的价格连乘；表内价格为执行值。第三关上限调整见后续内容。

| 项 | 每级效果 | 上限 | 价格（1→5 级） | 升满合计 |
|---|---|---|---|---|
| 城墙加固 | 城墙血量 +6 | 5 级 | 50 / 65 / 85 / 110 / 143 | 453 |
| 符笔 | 镇妖符伤害 +4% | 5 级 | 60 / 78 / 101 / 132 / 171 | 542 |
| 聚灵 | 灵气获取 +4% | 5 级 | 80 / 104 / 135 / 176 / 228 | 723 |
| 开坛 | 开局多选卡 1 次 | 1 级 | 400 | 400 |

开坛只有 1 级：第二关本身就送 2 次开局选卡，叠加太多会让开局完全没有压力。

**加成上限原则**：永久加成压小，局外的乐趣主要是"有进展、更有容错"，不是"数值碾压"。全部升满后：城墙 130、镇妖符伤害 +20%、灵气 +20%、开局多 1 次选卡、每种符咒伤害 +15%。普通难度零养成也必须能通关。

**加成计算契约** 🛠（不改变上述初稿比例）
- 开局冻结本局养成快照；成长只在局外购买，不能中途改变当前战斗。新局符咒等级、心法和灵气重置，局外属性与星级保留。
- 镇妖符伤害 `12 × (1 + 0.04×符笔级) × (1 + 0.2×本局朱砂级)`；符笔不强化六符或合击，星级也不强化镇妖符。
- 单符伤害 `第2.5节局内伤害公式 × (1 + 0.05×该符星级)`。星级不改冷却、冻结时长、弹数、范围或合击门槛；永久加成不重复加在命中事件上。
- 焚林使用加过青藤星级的区域 DPS，再乘第 2.5 节合击倍率，不额外乘烈焰星级；天河使用金光与寒冰各自加过星级的伤害之和再 ×2，不再乘第三次永久倍率。
- 直接命中先计算上述伤害，再乘第 2.2 节属性倍率，最后减目标有效固定护甲，最低 1；同一命中最多减一次护甲。持续区域按属性修正后的 DPS×dt 扣血，不逐帧扣固定护甲、不逐帧保底 1，避免帧率改变 DPS；生命与伤害保留小数，仅显示取整。
- 聚灵后每次灵气 `基础灵气 × (1 + 0.04×聚灵级)`，小数累计不丢；升级门槛仍按前一次整数门槛 ×1.3 四舍五入，余额跨级保留。例：聚灵 1 级连续获得 5 次基础灵气 1，共 5.2，首次升级后剩 0.2。
- 最大结界和开局选卡数按对应属性与本关基础值相加；回血使用统一上限，固元仍按第 2.5 节每秒固定回复。UI、模拟和正式战斗共用同一口径。

### 4.2 符咒星级 🧪

- 六种符咒开局全部可用，不做解锁。两组合击从第一局就都能凑出来，核心构筑不被养成卡住。
- 每种符咒可升 3 星，每星基础伤害 +5%，价格依次是 3、6、10 符纸（每种 19，六种合计 114）。星级只加数值，不改变符咒的效果。

### 4.3 存档

| 项 | 状态 |
|---|---|
| 关卡解锁进度（`fuzhen.unlockedLevels`） | ✅ |
| 铜钱、符纸、养成等级、符咒星级、首通记录 | 🛠 用一个 JSON 存到 `sys.localStorage`，带版本号 |

🛠 目标存档结构（版本 1；本稿尚未实现的格式，可在首次落地前补齐）：

```json
{ "v": 1, "revision": 0, "profileId": "本地随机唯一标识", "runSeq": 0,
  "activeRunId": null, "pendingSettlement": null, "lastSettlement": null,
  "unlockedLevels": 1, "coin": 0, "paper": 0,
  "stats": { "wall": 0, "brush": 0, "spirit": 0, "altar": 0 },
  "stars": { "metal": 0, "water": 0, "fire": 0, "earth": 0, "thunder": 0, "wood": 0 },
  "cleared": { "0": { "normal": false, "hard": false }, "1": { "normal": false, "hard": false } },
  "bestTimes": { "0": { "normal": null, "hard": null }, "1": { "normal": null, "hard": null } },
  "flags": { "metaTutorialSeen": false, "metaTutorialDone": false },
  "settings": { "music": true, "sfx": true, "shake": true } }
```

🛠 字段与恢复规则：
- `runId = profileId + ':' + runSeq`，开局先增加序号并持久化 activeRunId，成功才进入战斗。只允许当前 activeRunId 进入结算；新一局开始后旧战斗对象失效。只保留最近结算即可去重，不必无限增长 runId 列表。
- `pendingSettlement` 为 null 或不可变结果，包含 runId、结算规则版本、关卡、难度、结果 / 原因、活动秒数、击杀、开局养成快照、所有箱子的固定结果、奖励明细、是否首通、试玩记录。奖励明细的总和必须等于最终铜钱 / 符纸，不允许恢复时按新版表重算。
- `lastSettlement` 保存最近一次完整已提交结果并带 runId；提交时清 pending 与 activeRunId，增加余额、更新 cleared 和 bestTimes 一起写入。消费只能在没有 pending 时发生。
- `bestTimes` 按关卡、难度保存最短胜利活动时间，未胜为 null；失败、退出不写最佳，使用本局快照与相同难度比较，不跨难度覆盖。
- 整份 JSON 写 `fuzhen.profile`，上一有效快照写 `fuzhen.profile.bak`；每次提交 revision 加 1。验证主档与备份后选最高有效 revision，同 revision 优先主档；只把经验证的有效快照用作备份，不用损坏主档覆盖好备份。
- 每次先确保上一有效快照已有备份，再替换主档；备份写入失败时停止此次保存，保留当前有效主档。两个键不构成原子事务，必须用写入各阶段失败测试验证恢复结果；设置、升级也使用同一保存入口。
- 启动时若有 pending，则按已保存明细恢复提交；若 runId 已在 lastSettlement 中，只展示结果不加钱。若只有 activeRunId、没有 pending，记为进程中断并清 active，不发奖、不续战。
- 主档与备份均损坏、存储不可用或版本高于支持范围时，阻止覆盖并提示恢复 / 重试或用户主动清档，不自动生成新档覆盖旧数据。局部数值、枚举与上限校验，未知字段保留，非法升级与负余额拒绝加载。
- 试玩日志独立保存，按 runId 去重；日志写入失败不回滚已记账资源，可从 lastSettlement 补最近一条。备份恢复可能回退到上一有效快照，UI 说明恢复状态，不承诺损坏情况下绝对零回退。
- 首版只支持一个游戏实例写档；其他标签页 / 窗口进入只读或提示关闭，恢复前校验 revision。并行访问无法隔离的平台不得宣称多实例安全。

🛠 只有旧 `fuzhen.unlockedLevels` 时，校验并限制到现有关卡数；前 N 关保留访问权，仅前 N-1 关推断普通首通，不把最后开放关当作已通关。推断首通视为首通奖励已处理、不追补；困难首通、最佳时间和养成仍为默认。迁移成功再使用新档，保留旧键作来源，不在每次启动重复迁移。

状态规则：
- **红点**：养成、符咒入口在"有买得起的升级"时显示红点；记录不显示红点。
- **未解锁关卡**：箭头可以切到下一个未解锁关卡（只多一个），铭牌变暗并显示锁和"通关上一关解锁"，"出战"置灰。

- **首通奖励**：关卡牌底边一行小字显示当前关和难度的首通奖励，已领过显示"已领"。
- **数字显示**：资源数量四位以上用千分位（12,800）；超过 99,999 显示为"9.9万"格式。
- **默认关卡**：进入主界面时停在"最高已解锁且普通未通关"的关；全部通关则停在最后一关。

**结算页**（改造）：
1. 胜利 / 失败标题，存活时间、击杀数。
2. 按第 3.2.1 节先记账，成功后逐行展示：基础收益 → 精英额外铜钱与铜箱 → 首通额外奖励；开箱可跳过，展示不再次加钱。

### 4.5 失败引导 🛠

失败结算时，按下面的顺序挑一条建议，显示在奖励区下方：

| 条件 | 建议文案 |
|---|---|
| 死于 Boss 战，Boss 剩余血量 < 30% | "差一点！升级符笔，伤害更高" |
| 死于 Boss 出场前 | "城墙撑不住？升级城墙加固" |
| 本局最高等级低于预期（🧪 第一关 < 8 级） | "灵气不够？升级聚灵" |
| 上面都不满足 | 推荐当前买得起、且最便宜的一项 |

已满级的推荐项跳过，继续检查下一条；没有可升级项时给出集火 / 构筑建议，不推荐无法购买的满级属性。钱不够写明准确缺额，不承诺再打一局一定够。退出与进程中断不使用“被击败”的文案。

### 4.6 养成满级之后 🛠

培养进度按第 3.4 节样例与试玩统计，铜钱属性可能早于符咒升星满级。全部升满后目标是：
- 困难难度首通（额外符纸奖励，以及选关页上的金色印章）。
- 每关最短通关时间，显示在选关页上，只记本地。
- 🔭 第三关上线时，同时提高属性上限到 8 级，并加入新的消耗。

### 4.7 新手引导 🛠

- 第一局结束后，回到主界面时，右侧"养成"入口高亮闪烁，旁边一句提示："用铜钱加固城墙"。
- 第一次进入养成页解释城墙加固：够钱时高亮购买；不够时按真实余额显示“还差 X 铜钱”，玩家可自由返回，不承诺首局最低收入或下一局足够。
- 首次展示后记 `flags.metaTutorialSeen`，不再反复弹教学；首次成功购买任一属性后记 `flags.metaTutorialDone`。未买时仍能正常游戏，不强制停留。

### 6.3 平衡目标（只有这一套，🧪）

| 难度与养成 | 第一关通关率 | 第二关通关率 |
|---|---|---|
| 普通、零养成 | 60–80% | 40–60% |
| 普通、属性及六符星级全满 | ≥90% | 80–95% |
| 困难、零养成 | 记录观察，不设硬性通关率 | 同左 |
| 困难、属性及六符星级全满 | 50–70% | 30–50% |

🛠 测试口径：完成一次统一操作教学的触屏玩家，按同一游戏版本、相同规则与指定档案快照测试；每个有目标的“关卡 × 难度 × 养成”场景至少 3 人各打 5 局，顺序交错，记录每人既往经验，不能混入不同档位或键鼠结果。养成全满包含开坛；零养成仍保留六符可用。

通关率按该场景胜局 / 有效完整尝试计算，墙破和超时均是失败；技术中断、主动退出单独报告数量和原因，不静默丢样本。15 局只是初轮观察，记录胜 / 总局数，不将其宣称为统计置信结论；接近边界或不同玩家结果分化时追加同口径样本再定稿。

`scripts/balance-sim` 模拟不了真人瞄准与操作，用于固定策略比较版本，不直接套用真人目标。困难倍率和收益 / 分钟要一并检查，不能为了达到通关率只调奖励。

🛠 资源提交与日志恢复的职责见第 4.3 节；记录以 runId 去重。以下字段为目标结构，UI 导出必须包含实际版本与采样条件。
