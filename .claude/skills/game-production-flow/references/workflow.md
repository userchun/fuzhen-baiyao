# 游戏开发工作流

每个功能完成一次闭环，再进入下一功能。已有项目从真实缺口开始，不能每次重走全流程。

|阶段|主 Skill|辅助 Skill|产物|通过条件|
|---|---|---|---|---|
|01 需求与范围|game-production-flow|—|需求清单、统一待办、验收条件|范围和延期项明确|
|02 玩法与经济|game-rules-balance|tower-defense|规则与参数JSON、资源产消表|重大规则已确认；类型技能仅在适用时使用|
|03 关卡与节奏|level-design|game-rules-balance|波次、敌群、首领、教学与压力曲线|可玩的关卡逻辑及难度证据|
|04 界面与视觉规范|frontend-app-builder|imagegen|页面流程、设计图、尺寸/品质规范|按已确认设计评审；不擅自替换现有架构|
|05 角色与素材|imagegen|game-runtime-integration|阶段/品质素材、提示词、索引|透明度、轮廓、尺寸、裁切符合运行要求|
|06 动作与手感|game-feel|imagegen, game-runtime-integration|状态动作、投射物、命中特效、反馈音效|触发时序正确；普通克制、高阶差异化|
|07 功能接入|game-runtime-integration|—|可操作运行版本|真实路径使用正确素材和规则|
|08 存档与奖励|game-save-safety|—|迁移、幂等、冲突和续战证据|旧资产保留；失败可恢复|
|09 数值与回归|game-rules-balance|game-save-safety|多配置模拟与回归报告|使用正式引擎与正确配置|
|10 视觉与完整实战|game-acceptance-release|frontend-app-builder|真实操作、截图/录像、缺陷记录|正常胜负与成长闭环通过|
|11 移动端与性能|web-perf|game-acceptance-release|视口检查、真机和性能报告|区分浏览器、设备和估算证据|
|12 整理与交付|game-acceptance-release|game-production-flow|文档、素材索引、运行包和哈希报告|交付文件与已验证运行版本一致|

## 使用边界
- tower-defense 只用于适合的波次/自动攻击/经济分析；当前游戏没有塔摆放时，不引入其默认建造循环。
- frontend-app-builder 用于新界面或明确的重设计；小修和已批准界面按现有规范，不重新生图或迁移 React。
- imagegen 产出位图和关键帧，不能保证可直接使用的连续动画。必须人工/运行验证帧一致性。
- game-feel 负责反馈分层，不改变伤害、碰撞和经济规则。
- 本包没有虚构专用音频生成或 Cocos/微信发布 Skill；音效需现有工具或合法素材，引擎/平台适配需实际工具和官方文档。
- 其他 Skill 引用的可选技能不一定在包内；按需发现，不能假称已安装。

## 任务状态
待设计 → 待确认（仅必要规则）→ 制作中 → 接入中 → 待自动验证 → 待实战 → 待真机 → 已交付。
阻塞和延期单列；新消息默认补充当前任务；完成一项后继续已授权事项。

## 工作批次
推荐一个批次处理一个完整功能（例如伙伴选择→出战→技能→碎片→进化→恢复），而非先生成全部素材再集中接入。每批次更新同一待办和证据表。
